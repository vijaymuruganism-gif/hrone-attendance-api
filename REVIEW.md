# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 32–36) | Replaces hour/minute directly on UTC/naive `punch_in` with IST string components without timezone awareness. | Punching in at 09:35 IST gets compared against UTC time, producing arbitrary or negative offsets. | Converted `punch_in` explicitly to IST (`UTC+05:30`), created the shift start in IST on the attendance date, and checked if elapsed seconds strictly exceed 600s (R2). |
| 2 | `compute_late_minutes` (lines 35–36) | Uses `minutes > 10` on whole minutes. Fails boundary condition: punch at 09:40:01 IST (10 min 1 sec) was not marked late. | A test with 09:40:01 IST returned 0 instead of 10 late minutes. | Checked `elapsed_seconds > 600`, returning `elapsed_seconds // 60` (R2). |
| 3 | `compute_overtime` (lines 43–46) | Counts any overtime minutes immediately (`max(0, ...)`), missing the mandatory 30-minute minimum threshold (R3). | Punch-out 10 minutes after shift end returned 10 overtime minutes instead of 0. | Added threshold check `elapsed_seconds >= 1800` (30 min); otherwise returns 0. |
| 4 | `compute_overtime` (lines 43–46) | Does not handle overnight shifts (`shift_end <= shift_start`). Shift end is always placed on `date_str`, causing overnight shift overtime calculations to be negative or off by 24 hours. | Overnight shift (22:00 - 06:00) punching out at 06:40 IST next day computed overtime against yesterday's 06:00. | When `shift_end <= shift_start`, advanced the shift end target date by +1 calendar day. |
| 5 | `compute_work_hours` (line 39) | Uses Python built-in `round(..., 2)`, which applies Banker's Rounding (round-half-to-even) instead of round half-up (R4). | Values like 2.525 rounded down to 2.52 instead of 2.53. | Implemented `round_half_up` using Python's `decimal.Decimal` with `ROUND_HALF_UP`. |
| 6 | `create_employee` (lines 68–74) | Allowed `shift_start == shift_end`, violating the contract. Also sets naive `datetime.now()` without UTC conversion or truncation to seconds. | Inserting an employee with identical start/end times returned 201 instead of 422. | Added validation raising 422 if `shift_start == shift_end`. Truncated UTC instants to seconds and converted `created_at` to epoch milliseconds in output. |
| 7 | `create_employee` (line 69) | Relied on check-then-insert (`find_one` then `insert_one`), creating race conditions where concurrent requests with duplicate `emp_code` both get 201. | Concurrent requests for the same `emp_code` created duplicates or 500 errors. | Created a unique index on `emp_code` and caught `pymongo.errors.DuplicateKeyError` to return 409. |
| 8 | `list_employees` (line 82) | Buggy offset calculation: `skip = page * page_size`. Page 1 skipped the first 20 records! | Calling `GET /employees?page=1` returned items 21–40. | Changed to `skip = (page - 1) * page_size`. Also fixed `total` to count filtered documents `count_documents(q)`. |
| 9 | `punch_in` (line 89) | Did not handle unknown employee: `emp["shift_start"]` threw unhandled `TypeError` (500) if `emp` was `None`. | Punching in with a non-existent `emp_code` caused a 500 server crash instead of 404. | Added employee existence check returning 404 if not found. |
| 10 | `punch_in` (lines 90–91) | Computes attendance `date` using local server date (`ts.date()`), failing overnight shifts where punch-in is before `shift_end` (R1). | Overnight punch-in on July 7 at 01:15 IST recorded date as `2026-07-07` instead of `2026-07-06`. | Implemented `compute_attendance_date` with overnight detection per R1. |
| 11 | `punch_in` (line 107) | Returned internal `_id` as `"id": str(res.inserted_id)`, which is strictly forbidden by the contract. | Response schema validation failed on unexpected `"id"` field. | Removed `id` and `_id`; serialized record strictly per `AttendanceRecord` schema. |
| 12 | `list_attendance` (lines 131–134) | Loaded the entire collection into memory (`list(db.attendance_logs.find(q))`) and performed Python in-memory sorting and pagination. | Memory exhausted and request timed out on 100k records. | Implemented database-level sorting `.sort([("date", -1), ("emp_code", 1)])`, `.skip()`, and `.limit()`. |
| 13 | Global / Startup | No indexes created at startup except default `_id`. | `/admin/explain` showed `COLLSCAN` across all queries and aggregations. | Added `init_indexes()` in lifespan creating indexes on `emp_code`, `("emp_code", "date")`, `("date", "emp_code")`, `joined_on`, and `department`. |

### Non-defects:
- **`app = FastAPI(version="2.0.0")`**: Kept as-is because version 2.0.0 matches the API version specified in `openapi.yaml`.
- **`pydantic` models without `ConfigDict(extra="ignore")`**: Kept standard Pydantic models; FastAPI and Pydantic v2 strip extra fields by default when serializing response models.
